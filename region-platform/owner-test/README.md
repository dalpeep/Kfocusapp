# Issue #138 owner-test QA 운영 기록

전용 Netlify QA 초안은 `https://colorado-qa--online-business-directory-qa-138.netlify.app`이다. 호스팅 팀의 공유 환경 변수가 없음을 확인하고 저장소가 연결되지 않은 별도 사이트를 만들었다. 배포에는 owner-test 공개 API 키와 전용 게이트 비밀값만 설정했다. Supabase 서비스 역할 키나 Dallas 변수는 사용하지 않는다.

## 적용한 범위

- Supabase `aaikttogoejfvxbosktg`에 [추가 마이그레이션](001-owner-test-qa.sql)을 적용했다. `online_directory_qa`에 지역 레코드, 전용 계정, 이미지, 감사 기록을 저장한다. 지역 JSON에 승인본·대기본, 카테고리, 소유권 신청을 구분한다. UUID 버전 비교로 동시 덮어쓰기를 방지한다.
- 공개 Data API를 통과하는 전용 RPC는 서버 게이트 비밀값을 확인한다. 비밀값과 QA 계정 인증 검증값은 해시 형태로 전용 DB에 저장한다. RPC는 RLS를 우회할 수 없는 기능 전용 NOLOGIN 역할로 실행된다. 신원을 확인한 뒤 지역 범위를 지정한다. 웹 함수에서 역할·업소 소유권을 추가 확인하며, 웹 브라우저에는 게이트 비밀값을 전달하지 않는다.
- QA 총괄, 지역 관리자, 업주 역할은 기존 Supabase Auth 계정과 별개다. 업주는 자기 업소의 등록·수정·이미지 제출과 공개 승인본에 대한 소유권 신청을 할 수 있다. 지역 관리자는 자기 지역만 관리한다. 총괄 관리자만 지역을 생성하고 설정할 수 있다.
- PNG/JPEG 업로드는 파일당 최대 350 KiB이며 지역당 30개다. 이미지 바이트는 RLS가 적용된 신규 비공개 DB 테이블에 저장하고, 같은 지역에서 승인된 공개 이미지이거나 권한이 확인된 경우에만 전달한다. 기존 버킷과 정책 보존을 위해 Supabase Storage 버킷은 추가하지 않았다. 운영용 대용량 파일 보존이나 이미지 변환은 별도 설계가 필요하다.
- 실제 Colorado 후보는 주 전체 단위의 빈 비공개 지역으로 만들었다. 별도 비공개 `colorado-fixture`에서만 업주·관리자 테스트를 진행한다. 기존 Blobs 데모는 그대로 유지하며 레코드를 일괄 이관하지 않았다.

## 검증과 중단

브라우저 검증은 `tests/region/owner-test-online.test.mjs`를 사용한다. QA 전용 주소와 세 테스트 계정 암호는 환경 변수로만 전달한다. 테스트 레코드는 비공개 시험 지역에 생성된다. 실물 정보와 개인정보를 입력하지 않는다.

중단할 때는 전용 Netlify 초안을 비활성화하거나 해당 사이트의 게이트 비밀값을 비활성화한다. 기존 Blobs 데모와 레거시 owner-test 기능은 이 배포에 의존하지 않는다. 전용 스키마 데이터나 이미지를 삭제하는 작업은 이 절차에 포함하지 않는다.

Netlify QA 팀의 기본 로그인 보호가 초안에 적용된다. 팀 로그인 이후 온라인업소록 QA 계정으로 로그인한다. 브라우저 자동 검증은 로컬에서 동일한 함수 코드를 실행하되 실제 owner-test 데이터베이스에 연결하는 모드에서 수행했다. 호스팅 주소에서는 팀 로그인 차단 응답을 확인했다.
