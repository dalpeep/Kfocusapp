# 전체 커뮤니티 게시 기간 확장 검토

현재 운영 업체홍보는 `community_posts.publish_starts_at`과 `expires_at`을 사용합니다. 행사안내는 일반 커뮤니티 글의 행사 분류와 운영자 작성 행사 글을 모두 표시합니다. 기존 운영자 글은 별도 `public.posts`에 저장되며 날짜 필드와 활성·공개 플래그를 사용합니다.

| 대상 | DB 변경 범위 | 유지할 동작 |
| --- | --- | --- |
| 일반 커뮤니티와 행사안내 | `community_posts.publish_ends_at`을 nullable로 추가하고 관리자 저장 및 공개 조회에 기간 조건 적용 | 기존 글의 미설정 날짜, 등록일, 행사 일정, 승인 흐름 |
| 사고팔기·부동산 | 관리자 기간 저장 시 기간과 기존 만료·정리 시각의 관계를 함께 검증 | 판매완료는 재게시하지 않으며, 기존 보존 기간과 정리 조건 유지 |
| 기존 운영자 글 | `posts`에 독립적인 관리자 게시 시작·종료 필드를 추가하고 운영자 읽기 경로에 적용 | `event_start_at`·`event_end_at`, 기존 날짜 필드, 활성·공개 상태, 고정 순서 |

새 필드는 기존 행에 채우지 않습니다. 관리자가 날짜를 저장한 게시글만 새 날짜 검사의 영향을 받습니다. 날짜 변경으로 재게시할 수 있는 상태를 게시중과 만료로 제한합니다. 승인대기, 숨김, 거절, 삭제, 판매완료는 기존 상태 전환 경로를 유지합니다.

현재 공개 `community_posts` 조회 함수들의 서명과 권한을 유지하면서 목록, 상세, 댓글, 조회수에 같은 게시 기간을 적용합니다. `posts`는 공개 REST 조회가 있으므로 직접 공개 요청, 상세 링크, 홈 카드, 알림 및 행사 목록에 기본값과 우회 경로가 없는지 확인해야 합니다. 운영자 글에 새 공개 조회 함수나 기존 공개 정책 변경이 필요하면 해당 경로만 대상으로 합니다.

게시 기간 변경은 본문과 이미지 저장과 분리하고, 저장 후 같은 기준으로 상태 카운터를 갱신합니다. 운영 QA 전후에 게시판별 공개 글 수와 기존 글의 목록을 대조합니다. 긴급 롤백은 웹 배포 복원과 기간 편집 중단을 먼저 수행합니다. 미래 시작 글을 조기 노출할 수 있는 상태에선 공개 조회 조건을 되돌리지 않으며, 저장된 기간과 이력은 보존합니다.
