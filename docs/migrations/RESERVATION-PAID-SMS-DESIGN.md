# 유료 업주용 예약 SMS 설계

## 권한과 기존 동작

예약의 기본값은 OFF다. 예약을 켠 업소는 신청, 승인, 거절, 취소와 기존 이메일 알림을 무료로 이용한다. SMS는 별도 유료 권한이다. 초기 권한 부여·회수는 서버가 검증한 `super_admin`에게만 허용하는 것으로 설계한다. 업주는 기존 승인 소유권 검사에 통과한 자기 업소의 SMS ON/OFF와 유형별 설정만 관리할 수 있다. 유료 권한은 기본 미부여, SMS 설정은 기본 OFF다.

실제 발송 직전에 전역 활성화 설정, 업소별 유료 권한의 시작·종료 시각과 회수 여부, SMS 및 유형 설정, 예약의 현재 상태, 수신자 동의·차단, 월 한도를 모두 검사한다. 예약 OFF는 신규 접수만 막으므로 이미 확정된 미래 예약의 알림에는 업소 SMS 설정을 별도로 적용한다. 권한 해제·만료나 SMS OFF 이후 아직 제출되지 않은 작업은 건너뛴다. 이미 제공업체에 넘어간 메시지는 회수할 수 없으며 이 경계를 운영 화면에 명시한다.

## 필요한 데이터

아래는 향후 구현할 논리 구조다. 이번 작업에는 마이그레이션이 없다. 기존 예약 UUID, 업소 UUID, 현지 시간대, 예약 전화번호를 재사용한다.

| 구조 | 주요 항목 및 제약 |
|---|---|
| 업소 SMS 이용 권한 | 업소 UUID, 적용 시작·종료, 회수 시각, 부여 관리자, 월 세그먼트 한도, 변경 사유 및 감사 기록 |
| 업소 SMS 설정 | 업소 UUID, 전체 ON/OFF, 신청·확정·거절·취소·리마인더 각각의 설정. 업주 수신처는 검증된 승인 소유자와 연결하고 별도 동의를 저장 |
| 예약 SMS 동의 | 예약 UUID, 업소 UUID, 수신 번호의 키 기반 식별값, 동의 여부, 서버 기록 시각, 안내 문구 버전, 예약 폼 출처, 철회 시각 |
| 수신 거부 | 발신 서비스 범위와 정규화 번호의 키 기반 식별값, 거부·재동의 상태 및 시각, 검증된 이벤트 ID |
| 발송 대기열·결과 | 예약 UUID, 업소 UUID, 이벤트, 대상 역할, 예정 시각, 상태, 시도 횟수, 임대 만료, 메시지 ID, 중복 방지 키, 세그먼트 수 및 정제된 오류 코드 |
| 월 사용량과 단가 | 업소 UUID와 청구 월별 예약·확정 세그먼트 및 결과 집계. 적용일·통화가 있는 별도 단가 버전과 제공업체 정산 결과 |

예약·업소 연결은 서버가 기존 레코드에서 확인한다. 결합 관계는 DB에서도 검증한다. 테이블은 비공개 스키마와 RLS로 기본 차단하고, 승인된 서버 경로만 조회·변경한다. 관리자 전체 사용량 및 업주 본인 집계에는 수신 번호, 메시지 본문, 예약 비밀번호를 포함하지 않는다.

## 발송 및 확장 인터페이스

기존 예약 상태 변경을 기준으로 SMS 대기열을 추가한다. 이메일의 `reservation_mail` 트리거·큐·제공업체는 독립적으로 유지한다. 예약 트랜잭션 안에서는 대기열에만 기록하고 외부 호출은 커밋 후 별도 워커에서 수행한다. 대기열 예외는 개인정보 없이 기록하고 예약을 성공시킨다. 누락 복구는 보존된 상태 전이 기록을 근거로 하며 과거 예약을 무조건 재발송하지 않는다.

| 예약 이벤트 | 수신자 및 조건 |
|---|---|
| 신규 신청 | 승인된 업주 중 검증된 수신처와 별도 동의가 있는 대상 |
| 승인 | 해당 예약의 문자 동의 고객 |
| 거절·취소 | 해당 예약의 문자 동의 고객. 업주·고객 어느 쪽이 취소해도 동일 예약의 취소 이벤트는 한 번 처리 |
| 전날 리마인더 | 예약 전날 업소 현지 시각 오전 10시를 초기 기본값으로 사용. 해당 시각 전에 확정된 예약만 대상으로 하며 발송 직전 확정 상태를 재검증 |

리마인더는 업소의 IANA 시간대에서 현지 예약일의 전날을 계산한 후 UTC로 저장한다. 일광절약시간 경계도 검사한다. 이미 리마인더 시각이 지난 예약은 뒤늦게 발송하지 않는다. 일정이 바뀌면 이전 예약 시각으로 생성된 대기 작업을 무효화한다.

- 서버 설정 인터페이스는 업소와 현재 인증 사용자만 받아 기존 소유권을 검증한다. 관리자 권한 인터페이스는 업소·기간·월 한도·사유만 받는다.
- 대기열 API는 예약 상태 전이와 대상 역할로 작업을 생성한다. 브라우저에서 수신처, 본문, 발신 번호를 지정할 수 없다. 작업 중복 키에는 예약 UUID·상태 전이 또는 일정 버전·대상 역할을 사용한다.
- 워커는 DB에서 작업과 월 한도 사용량을 원자적으로 확보한 뒤 승인된 템플릿으로 렌더링한다. 제공업체 어댑터는 `send({senderRef, toE164, body, idempotencyKey})`와 서명이 검증된 `parseWebhook(request)` 계약을 제공한다.
- 상태는 대기, 처리 중, 제공업체 접수, 전달, 실패, 제외, 결과 불명으로 구분한다. 제공업체 접수는 실제 전달과 별개다. 임대가 만료됐거나 네트워크가 끊긴 요청은 제공업체 조회 또는 멱등 키로 결과를 확인한 뒤 재시도한다. 결과를 확인할 수 없고 제공업체가 중복 방지를 보장하지 않으면 자동 재발송하지 않는다.
- 상태·수신 거부 웹훅은 제공업체 서명을 검증하고 이벤트 ID로 재생을 막는다. 순서가 뒤바뀐 상태 이벤트가 전달 완료를 대기 상태로 되돌리지 못하게 한다.
- 메시지는 발신자 표시, 예약 상태, 업소 현지 일시, 인증이 필요한 일반 관리 링크까지만 담는다. PIN, 조회용 비밀값, 고객 이름·전화번호·요청사항은 본문·URL·로그에서 제외한다.

## 고객 동의와 STOP

예약 폼에 기본 해제된 선택 항목을 둔다. 예시 문구는 “이 예약의 상태 변경과 리마인더를 문자로 받겠습니다.”다. 실제 등록에 사용할 화면에는 발신자, 메시지 유형과 빈도, 비용 안내, STOP·HELP, 개인정보 처리방침을 제공업체 요건에 맞춰 표시한다. 미동의, 번호 형식 오류, SMS 발송 실패는 예약 저장과 기존 이메일에 영향을 주지 않는다. 업주 알림도 별도로 동의한 검증된 업주 번호에만 보낸다.

전화번호는 US 출시 기준 E.164로 정규화한다. 발송 시 기존 예약의 번호를 서버에서 가져오고 동의 시점에 연결한 번호와 일치하는지 확인한다. 번호 변경은 기존 동의를 재사용하지 않는다. STOP은 사용 중인 발신 서비스의 실제 차단 범위에 맞춰 즉시 저장하고 미전송 작업을 제외한다. 공용 발신 서비스에서는 업소 간에도 해당 수신 거부 범위를 적용한다. 예약 폼에서 다시 체크해도 STOP은 해제되지 않는다. 재동의는 제공업체가 지원하는 명시적 절차로 확인한다. 광고는 별도의 동의·캠페인·발송 경로로 분리한다.

## 사용량과 비용

프리미엄 SMS 요금은 업소별 월 **$19.99 USD**이며 월 **200 SMS 세그먼트**를 포함한다. 초과 요금은 **100세그먼트당 $2.00 USD**를 잠정 가격으로 기록한다. 초기 구현은 포함량 200에서 발송을 차단하고 초과 과금은 비활성화한다. 향후 초과 사용을 허용하기 전에 과금 단위의 올림 여부와 청구 월 경계를 확정한다.

월 한도는 메시지 건수가 아닌 과금 가능한 세그먼트로 관리한다. 업소별 청구 월의 시간대는 계약 정책으로 고정한다. 본문 인코딩과 길이로 예상 세그먼트를 계산해 DB 트랜잭션에서 한도를 선점하고, 제공업체의 실제 세그먼트 수와 정산 내역으로 확정한다. 명확히 미과금인 실패분만 반환하고 결과 불명은 정산 전까지 유지한다. 한도를 넘으면 SMS만 제외한다. 업주 화면은 월 한도·사용량·실패 건수를, 관리자 화면은 업소별 집계와 전체 사용량 및 정산 차이를 보여준다.

예상 비용은 월 세그먼트 × (제공업체 단가 + 통신사 수수료)에 발신 번호·등록·캠페인 비용과 청구 대상 수신 문자를 더해 계산한다. 한국어 템플릿은 유니코드 분할을 실제 공급업체 기준으로 확인한다. 단가는 버전과 적용일을 두고 과거 정산을 고정한다. 계약과 단가를 확정하기 전에는 실제 금액이나 자동 청구를 설정하지 않는다.

## 단계별 구현 계획

구현 순서는 관리자 전용 권한 부여·회수 및 감사 기록, 업소별 월 사용량과 원자적 한도 집계, 업주 설정과 모의 발송, 지정 업소 발송 검증 순이다. 구독 결제 및 초과 과금은 별도 단계로 남긴다.

1. 기존 예약 상태 전이와 소유권 계약을 기준으로 격리 DB에 최소 구조를 설치한다. 권한, 동의, 한도 동시 처리, 중복 작업, 다른 업소 접근, 실패 후 예약·이메일 회귀를 테스트한다.
2. 업주 설정·관리자 권한 화면·예약 선택 동의를 구현한다. 모의 제공업체로 STOP, 위조 웹훅, 상태 순서 역전, 불명 응답과 중복 방지, 현지 시간 리마인더를 확인한다.
3. 공급업체와 발신 방식, 캠페인, 예상 비용, 보관 기간과 개인정보 절차를 확정한다. 미국 10자리 지역번호 경로를 선택하면 해당 제공업체의 A2P 10DLC 브랜드·캠페인 등록 및 발신 번호 연결을 준비한다. 동의 화면, 정책 링크, 메시지 샘플, STOP·HELP 검증 자료를 준비한다. [A2P 10DLC 등록 가이드](https://www.twilio.com/docs/messaging/compliance/a2p-10dlc/quickstart) · [비용 구성 참고](https://help.twilio.com/articles/1260803965530-What-pricing-and-fees-are-associated-with-the-A2P-10DLC-service-)
4. 승인 후 서버 실행 환경에 비밀값과 웹훅 서명 검증을 설정하고, 별도 스케줄러를 최소 권한으로 연결한다. 허용된 테스트 번호에 한해 전달·STOP·정산을 검증한다.
5. 운영 전체는 기본 OFF로 출시하고 지정 업소만 유료 권한과 SMS를 켠다. 이상 시 전역 SMS 스위치를 내려 신규 발송을 차단하고 대기열과 감사 기록을 보존한다. 예약과 이메일 회귀를 확인한다.
