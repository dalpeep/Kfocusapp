9. 렌더링 원인 확정 및 후속 수정 — 2026-11-02
앞선 8절의 렌더링 원인 미확정/FAIL은 다음 재현으로 해소했다.
- 동일 ZIP과 동일 Node 22.23.4에서 /tmp를 noexec로 마운트하면 native sharp .node 로딩이 failed to map segment from shared object로 실패한다. sharp는 WASM으로 fallback하고, 이 런타임에는 Pango/text가 없어 VipsOperation 오류가 발생한다.
- /tmp를 exec 가능한 격리 tmpfs로 바꾸자 동일 ZIP이 native libvips/Pango를 사용하고 기존 renderPng가 정상 작동했다. 쿠폰 레이아웃/폰트/색상/업무 정책 변경이나 sharp 버전 변경은 필요하지 않았다.
- 렌더러에 Pango 지원 확인을 추가해 잘못된 런타임이면 TEMPLATE_TEXT_RUNTIME_UNAVAILABLE로 명확히 실패시킨다. 이미지 생성을 생략하거나 빈 이미지를 반환하지 않는다.
- 실제 PNG 생성, 각 텍스트 영역 픽셀, 한글 문자열별 bitmap 변화, 특수문자, 파일 저장/재읽기, Paid PNG/JPEG/WebP와 5MiB 차단을 검사한다. 가상 쿠폰 4종을 시각 확인해 한글 표시 PASS.
- 로컬 Owner 검사 143 PASS / 0 FAIL(이번 렌더 8개 포함). 수정 후보 ZIP 종합 검사: imports49/SDK49, Owner OFF4, 렌더8, 이미지형식6, 용량초과2, 권한11 PASS. noexec 증거는 보존한다.
- 원격 CI 실행을 위해 이 개발 브랜치의 Push를 기존 Owner QA/Release QA 워크플로에 추가한다. 두 워크플로 모두 배포 작업이 없다. Netlify ignore=exit 0 및 Preview 승인 게이트는 그대로다.
